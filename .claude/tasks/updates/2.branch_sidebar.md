# Task: Branch Management with company sub-pages in the Admin Console

## Context
- Repo: `RamKatwal/Multibranch` (Providhy 3), live at https://multibranch-kohl.vercel.app/admin
- Stack: Next.js App Router, TypeScript, Tailwind, shadcn/ui
- An account can have multiple **companies**, and each company has multiple **branches** (Head Office + others). See `claude/multi-branch-spec.md` for the branch model.
- Right now branch management lives at `/admin/organizations/branch-management`, nested under a company in the sidebar's Organizations list. The URL has no company ID, so every company's branch page shares the same URL.

## Goal
Make **Branch Management** a top-level sidebar item. Its sub-items are the **company names**. Clicking a company shows that company's branches.

```
Home
Branch Management        → all companies overview
  ABC Company  2         → ABC's branches
  Notion       1         → Notion's branches
User Management
Subscriptions
```

## What to build

### 1. Sidebar
- Add a collapsible "Branch Management" item. Its children are the companies the current user can access, with each company's branch count shown beside its name.
- If the account has only one company, show no children, and "Branch Management" links straight to that company's branches.
- If there are more than 6 companies, show the first 6 plus a "View all" link to the overview page.
- When you're on any branch page, highlight both the parent and the active company.
- Remove the old per-company "Branch Management" sub-link under Organizations, so companies aren't listed twice in the sidebar.

### 2. Routes
- `/admin/branches` is the overview of all companies.
- `/admin/branches/[companyId]` shows one company's branches. Build it as one dynamic route, not one page per company.
- Redirect `/admin/organizations/branch-management` to `/admin/branches`.
- Breadcrumb: Admin › Branch Management › {Company name}

### 3. Overview page (`/admin/branches`)
- Header: title "Branch Management" and a usage label such as "2 of 3 branches used". The limit is account-wide.
- List the branches grouped by company. Each company group has a header with its name, branch count, and a "+ Add branch" button.
- Clicking a company name goes to `/admin/branches/[companyId]`.

### 4. Company branches page (`/admin/branches/[companyId]`)
- Reuse the existing table. Columns: Branch name, Branch code, Location, Status, Created date, Actions.
- Show one "Add branch" button and remove "Quick branch setup".
- Actions per row: Edit (name and location only), plus Deactivate/Activate.
- Head Office row: show a "Head Office" badge and don't allow it to be deactivated.

### 5. Add branch dialog
- Fields: Branch name, Branch code, Location. When opened from a company page or a company group, the company is already set. When opened anywhere else, show a Company select.
- Auto-suggest the branch code from the name (for example, "Kathmandu Hub" → "KTM"). Codes must be unique within the company. Helper text: "Can't be changed later."
- If the branch limit is reached, the button still opens the dialog. The dialog shows an "Add more branches" step instead (a mock upgrade step is fine for now), then continues to the form.
- On success, show the toast "Branch created" with an "Assign users" action that links to User Management.
- In Edit mode, the branch code is read-only.

### Data
- Use mock data / the existing helpers in `lib/` for companies and branches. Reuse Multibranch's existing branch types (e.g. Head Office "HO"). Don't add new duplicate types.

## Out of scope
- Real payment for buying extra branches
- Changes to User Management, other than linking to it
- Any `(dashboard)` / ERP pages outside `/admin`

## Acceptance criteria
- [ ] The sidebar shows Branch Management with companies as children, plus branch counts. The active state works.
- [ ] `/admin/branches` and `/admin/branches/[companyId]` render correctly for every company. The old URL redirects.
- [ ] The add, edit and deactivate flows work. Head Office is protected. The branch code can't be edited after creation.
- [ ] The limit-reached state appears when branches used = limit.
- [ ] With one company only, there are no sub-items and the link goes straight to the branches page.
- [ ] No regressions in other admin pages. `npm run lint` and `npm run build` pass.

## Deliverable
Create the branch `feature/branch-management-sidebar`, commit in small steps, and open a PR to `main` with screenshots of the sidebar, the overview page, a company page, and the add-branch dialog (normal and limit-reached). If something conflicts with the existing branch model and the right choice isn't clear, stop and ask.
