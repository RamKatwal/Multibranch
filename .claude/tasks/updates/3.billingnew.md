# Task: Single Billing page in the Admin Console

## Context
- Repo: `RamKatwal/Multibranch` (Providhy 3). Stack: Next.js App Router, TypeScript, Tailwind, shadcn/ui.
- Reference: Providhy 2 sandbox billing page at https://providhy-2-0.vercel.app/admin/billing
- Today v3 has `/admin/subscriptions`, a **list** of subscriptions with a detail page. v2 uses **one billing page** for the whole account: a single plan, with no list to pick from.
- **Use v2 for what the page contains. Use v3 for how it looks.** v2's design is different, so build everything with Providhy 3's existing admin components, tokens and patterns. Don't copy v2's styles.

## Goal
Add a new **Billing** page at `/admin/billing` that follows v2's single-billing structure. Keep the old subscriptions page available as **Billing v2**, shown greyed out at the bottom of the sidebar.

## 1. Sidebar
```
Home
Branch Management
User Management
Billing              → /admin/billing (new)
...
──────────
Billing v2           → /admin/subscriptions (greyed out, at the bottom)
```
- Add **Billing** to the main nav, in the slot where Subscriptions sits today.
- Move the old Subscriptions item to the **bottom** of the sidebar and rename it **Billing v2**. Show it greyed out with muted text and icon. It must still be clickable and still open `/admin/subscriptions`.
- Don't change the `/admin/subscriptions` pages themselves.

## 2. Billing page (`/admin/billing`)
The page shows these sections, top to bottom. Reuse the existing `components/admin/subscriptions/sections/*` (current-plan, capacity-meter, invoices, payment-method, branch-allocations) and the existing dialogs wherever they fit.

**a. Current plan card (left, wide)**
- Plan name with a "Current Plan" badge, then "Active until {date} · {Yearly/Monthly}".
- Stats row: Days left, Companies `used / limit`, **Branches `used / limit`** (v3 only), Users `used / limit`, Next renewal amount (Rs.).
- When a limit is reached, show an inline warning under that stat, e.g. "Limit reached. Add slots to create more companies."
- Actions: **Add company**, **Add branch**, **Add users**, **Renew**. Each opens the existing v3 dialog for that action.

**b. Subscribed Modules card (right)**
- Subtitle: "These modules are available in all your companies."
- Module chips: Sales, Purchase, Inventory, Accounting, Reports.
- Action: **Add module**.

**c. Billing details**
- Who is billed: a badge (Company or Individual) plus the name, e.g. "ABC Company".
- Action: **Change**. It opens a dialog to switch between Company and Individual and pick the company or enter the person's details.
- Empty state when billing details aren't set yet, with a "Set billing details" action.

**d. Payment History**
- Table columns: Date (sortable), Description, Billing Cycle, Payment Period, Amount (sortable, right-aligned), Actions (View).
- **View** opens the existing invoice receipt view.
- **Export** button in the header.
- Empty state: "No payments yet".

**e. Renewal states**
- Handle three states: Active, Expiring soon (e.g. 60 days left: show a warning banner with Renew), Expired (show an error banner, and Renew becomes the primary action).
- For testing, a small dev-only switcher like v2's sandbox panel is fine (renewal scenario: Default / 60 days left / Expired; bill to: Company / Individual / None). Hide it in production builds.

## Data
- Use mock data from the existing helpers in `lib/`. Reuse the plan, subscription and branch types that already exist, and don't add duplicates.
- Plan and limits must match `/settings/billing-plans` and the Branch Management usage ("2 of 3 branches used").

## Out of scope
- Real payments or a payment gateway
- Changes to `/admin/subscriptions` (Billing v2) beyond the sidebar label and position
- `(dashboard)` / ERP pages outside `/admin`

## Acceptance criteria
- [ ] The sidebar shows **Billing** in the main nav and **Billing v2** greyed out at the bottom. Both links work and the active state is correct.
- [ ] `/admin/billing` shows the plan card, modules, billing details and payment history, styled like the rest of the v3 admin.
- [ ] Add company, Add branch, Add users, Renew, Add module, Change billing details and View invoice all open working dialogs.
- [ ] Limit-reached, expiring-soon, expired and empty states all render.
- [ ] Billing v2 (`/admin/subscriptions`) works exactly as before.
- [ ] `npm run lint` and `npm run build` pass.

## Deliverable
Create the branch `feature/single-billing`, commit in small steps (sidebar → page sections → states), and open a PR to `main` with screenshots of the sidebar, the Billing page, and the expired state. If v2 and v3 conflict and the right choice isn't clear, stop and ask.
