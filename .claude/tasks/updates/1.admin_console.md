# Task: Port the Admin Console from `RamKatwal/erp` into Providhy 3 (`RamKatwal/Multibranch`)

## Context
- **Providhy 3** = `https://github.com/RamKatwal/Multibranch` (live: https://multibranch-kohl.vercel.app/). This is the target repo.
- **Source** = `https://github.com/RamKatwal/erp` (live admin: https://erp-tan-rho.vercel.app/admin). Providhy 3 was originally cloned from this repo and has since diverged (multi-branch support, trial banner, billing plans, updated dashboard, etc.).
- The admin console already exists in `erp` and was designed to match the admin console added to Providhy 2 (https://uat-apps.providhy.com). We now need the same admin console inside Providhy 3.
- Stack (both repos): Next.js App Router, TypeScript, Tailwind, shadcn/ui.

## Goal
Bring the full admin console (`/admin/*`) from `erp` into `Multibranch`, so it works with Providhy 3's current layout, components, branch model and styles — **without breaking or regressing anything in the existing Providhy 3 app.**

## Files to port from `erp`
**Routes – `app/admin/`**
- `layout.tsx`, `page.tsx`
- `companies/page.tsx`, `companies/[companyId]/configuration/page.tsx`, `companies/[companyId]/setup/page.tsx`
- `configurations/page.tsx`
- `organizations/page.tsx`, `organizations/branch-management/page.tsx`, `organizations/permissions/page.tsx`
- `settings/page.tsx`, `settings/branch-management/page.tsx`
- `settings/users-permissions/` → `layout.tsx`, `page.tsx`, `groups/`, `permissions/`, `users/`
- `subscriptions/page.tsx`, `subscriptions/[subscriptionId]/page.tsx`

**Components – `components/admin/`**
- `company-lists-page.tsx`, `organization-columns.tsx`
- `home/` → admin-home-page, kpi-strip, needs-attention-panel, organization-created-dialog, quick-actions, recent-activity-panel
- `setup/` → organization-setup-dialog, setup-progress-bar
- `subscriptions/` → all dialogs, billing-utils, invoice-receipt-view, order-payment-panel, stacked-avatars, subscription-columns, subscription-detail-page, subscriptions-page, and `sections/` (branch-allocations, capacity-meter, current-plan, invoices, payment-method)

**Layout – `components/layout/`**
- `admin-shell.tsx`, `admin-sidebar.tsx`, `admin-go-to-company.tsx`

**Also check & bring over anything these depend on** (types in `types/`, mock data/helpers in `lib/` or `config/`, hooks in `hooks/`, shadcn UI primitives in `components/ui/`, shared settings shells like `components/settings/users-permissions/users-permissions-shell.tsx`), plus any admin-related logic in `middleware.ts` or `app/api/`.

## How to do it
1. **Clone both repos** and compare first. Before copying anything, list:
   - files that exist only in `erp` (safe to add),
   - files that exist in both but differ (shared components, `components/ui/*`, types, lib, `globals.css`, `middleware.ts`) — **do not overwrite these blindly**.
2. **Add admin-only files** as-is (routes + `components/admin/*` + admin layout files).
3. **For shared/diverged files**: keep the Multibranch version as the source of truth. Only add what the admin console needs (new exports, new types, new UI primitives, extra props). If a shared component's API changed in Multibranch, update the admin code to use the new API — not the other way round.
4. **Align with Providhy 3**:
   - Use Multibranch's design tokens, header pieces (search/Ctrl+K, notifications, profile menu) and patterns so admin looks like part of the same product.
   - Admin must be aware of Providhy 3's **multi-branch model**: branch management, branch allocations in subscriptions and permissions should use Multibranch's branch types/data (e.g. Head Office "HO") rather than erp's older shapes.
   - Subscriptions/plans in admin should line up with Providhy 3's `/settings/billing-plans` and trial/plan data where they overlap — reuse the same plan definitions instead of duplicating.
5. **Navigation between the two worlds**:
   - "Go to Company" in the admin header goes to the Providhy 3 dashboard (`/`) or branch selector as appropriate.
   - Add an entry point from the Providhy 3 app into `/admin` (e.g. in the profile menu) — keep it subtle, as in erp.
6. **Keep the existing app intact**: no changes to `(dashboard)` pages, sidebar items or routes unless needed to add the admin entry point.

## Acceptance criteria
- [ ] All `/admin` routes from erp render in Multibranch: Home, Organizations (+ branch management, permissions), Companies (+ setup, configuration), Configurations, Settings (+ branch management, users & permissions: users / groups / permissions), Subscriptions (+ detail page).
- [ ] Admin sidebar items and header (Go to Company, Ctrl+K search, notifications, profile) work; command palette opens.
- [ ] All dialogs open/close and work: add organization / setup, organization created, add / renew / cancel subscription, update plan limits, invoice receipt.
- [ ] Branch data in admin matches Providhy 3's branch model.
- [ ] Existing Providhy 3 pages (Home, Inventory, Purchase, Sales, Accounting, Reports, Configurations, Settings, billing plans, branch selector, onboarding) look and behave exactly as before.
- [ ] `npm run lint` and `npm run build` pass with no new TypeScript errors.
- [ ] No duplicated components — anything that already exists in Multibranch is reused.

## Deliverable
- Work on a new branch `feature/admin-console`, commit in logical steps (routes → components → shared changes → navigation), and open a PR to `main`.
- In the PR description include: list of added files, list of modified shared files with a one-line reason each, anything deliberately left out, and screenshots of the main admin pages.
- If something in erp conflicts with Providhy 3 and the right choice isn't clear, **stop and ask** instead of guessing.
