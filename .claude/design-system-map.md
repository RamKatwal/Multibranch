# Design System Map

Inventory of every UI component in use across the codebase, grouped by source
library, with file path and usage count. Generated by searching all imports
under `components/`, `app/`, `lib/`, and `types/` (excluding `node_modules`).

## Naming note: "Radian"

"Radian" is the name of the Figma design-system library this codebase
implements (`.cursor/rules/providhy-radian-design-system.mdc`). In code,
Radian = `components/ui/**`. It is built on **Base UI** (`@base-ui/react`)
plus `cmdk` for the command palette — the last Radix UI holdouts
(`label.tsx`, `form.tsx`'s `FormControl`) were removed on 2026-09-18 (see
"Consolidation status" below).

### Underlying primitives (wrapped by the above; never imported directly by feature code)

Confirmed via repo-wide search: zero direct imports of `@base-ui/react/*` or
`@radix-ui/*` outside `components/ui/`. Rule #1 in `CLAUDE.md` ("search
`components/ui/` first") is being followed in practice. This layer is
invisible to Figma parity — Radian's Figma fidelity is governed by the
`components/ui/*` component API, not by which headless engine sits under it.

- **Base UI** (`@base-ui/react/*`) — used in 19 wrapper files: `tabs`,
  `switch`, `tooltip`, `sidebar`, `popover`, `separator`, `sheet`, `input`,
  `drawer`, `dropdown-menu`, `dialog`, `collapsible`, `button`, `avatar`,
  `badge`, `breadcrumb`, `button-group`, `divider`, `otp-field`.
- **Radix UI** — none remain. The last wrapper file, `form.tsx`
  (`react-slot`, via `FormControl`), was migrated — see "Consolidation
  status" below.
- **cmdk** — `components/ui/command.tsx` only.

**Consolidation status (updated 2026-09-18):**

- **Done** — `divider.tsx` migrated to `@base-ui/react/separator` (was
  0-usage/dead, zero risk). `otp-field.tsx` migrated to
  `@base-ui/react/otp-field`; its one call site
  (`components/verification-form.tsx`, the email-verification/auth flow)
  was updated to match Base UI's API differences: `index` is now inferred
  automatically from render order (no longer passed as a prop), an explicit
  `length={6}` is now required on `<OTPField>` (Base UI doesn't infer it
  from children count the way Radix did), and `OTPHiddenInput` was removed
  since Base UI's `OTPFieldRoot` has no separate hidden-input part — this
  form is fully react-hook-form-controlled via `value`/`onValueChange`, so
  no native-form submission behavior was lost. Verified via `tsc --noEmit`,
  `eslint`, and confirming SSR output renders all 6 slots with no error
  overlay (an already-running dev server on the machine made a full
  interactive browser click-through impractical to script without
  disrupting that session — worth a manual click-through of `/verification`
  before shipping).
- **Also done (2026-09-18)** — centralized `toast()` under Radian.
  `components/ui/sonner.tsx` previously only wrapped the `<Toaster>`
  container; the `toast()` function itself was imported straight from
  `"sonner"` in 94 feature files, bypassing the design-system layer
  entirely. Added `export { toast } from "sonner"` to
  `components/ui/sonner.tsx` and repointed all 94 call sites to
  `import { toast } from "@/components/ui/sonner"`. Purely a re-export +
  import-path change — no behavior, styling, or call-signature changes —
  verified via `tsc --noEmit`, `eslint` across all 94 files, and a full
  `npm run build`, all clean. This closes the gap: if Radian's toast
  variant/icon/duration conventions ever change, there is now one file to
  edit instead of 94.
- **Also done (2026-09-18)** — `label.tsx` dropped `@radix-ui/react-label`
  entirely rather than migrating to Base UI's `Field.Label`. `Field.Label`
  requires a `Field.Root`/`Labelable` context ancestor (it throws without
  one — confirmed by reading `FieldRootContext.js`'s `useFieldRootContext`),
  and none of this app's 3 real call sites (`stock-transfer-2`,
  `stock-transfer`, `permission-management-page`) use `Field.Root` — each
  just pairs a plain `<Label htmlFor="...">` with a matching input id.
  Reading Radix's own source showed `Label.Root` is just a native `<label>`
  plus an `onMouseDown` handler that blocks text-selection on rapid clicks
  (skipped when the click lands on an interactive child), so that behavior
  was hand-rolled directly in `label.tsx` — same precedent as
  `checkbox.tsx` being hand-built rather than wrapping a headless
  primitive. `@radix-ui/react-label` was removed from `package.json`.
  Verified via `tsc --noEmit`, `eslint`, and `npm run build`, all clean.
- **Also done (2026-09-18)** — `form.tsx`'s `FormControl` dropped
  `@radix-ui/react-slot` without touching any of its ~30 call sites.
  Adopting Base UI's `useRender` was rejected because it swaps the
  implicit-`asChild` API (`<FormControl><Input/></FormControl>`) for an
  explicit `render` prop, which would have forced editing every form.
  Instead, `FormControl`'s only actual requirement — clone its own props
  (`id`, `aria-describedby`, `aria-invalid`) onto its single child element
  — was hand-rolled as a small local `Slot` inside `form.tsx`, reading
  Radix's own `mergeProps`/`getElementRef` source to replicate its exact
  semantics: child props win over slot props for plain keys (so a call
  site that sets its own `id` still overrides `formItemId`, unchanged
  behavior), event handlers chain, `className`/`style` merge instead of
  overwrite, and refs compose. Radix's `Slottable`/lazy-child branches
  were skipped since no call site in this codebase uses them (confirmed
  by inspecting all `<FormControl>` usages). Verified via `tsc --noEmit`,
  `eslint`, `npm run build`, and an SSR fetch of `/signup` diffed against
  the expected merged output (`id="fullName"` still wins over
  `formItemId`, `aria-describedby`/`aria-invalid`/`data-slot` still land
  on the rendered `<input>`) — byte-for-byte the same merge result as
  before. `@radix-ui/react-slot` was removed from `package.json`. This
  closes out Radix UI entirely: Radian is now 100% Base UI (plus `cmdk`
  for the command palette).

## Summary

- The Radian design system (`components/ui/**`) is the dominant, correctly
  centralized source of shared UI, and its Base UI/Radix primitives are
  never leaked into feature code — the "search `components/ui/` first" rule
  is holding.
- Feature code reaches directly for a small, consistent set of
  non-visual/utility libraries (icons, forms, tables, toasts, charts,
  theming) rather than competing component kits.
- Two known violations (hand-rolled tabs) remain unfixed and should migrate
  to `components/ui/tabs` per `.cursor/rules/ui-tabs.mdc`.
- `divider.tsx` and `otp-field.tsx` are now on Base UI, `toast()` is now
  centralized through `components/ui/sonner.tsx` instead of being imported
  from `sonner` directly in 94 places, `label.tsx` has dropped
  `@radix-ui/react-label` in favor of a hand-rolled native `<label>`, and
  `form.tsx`'s `FormControl` has dropped `@radix-ui/react-slot` in favor of
  a hand-rolled `Slot` — see the "Consolidation status" notes above. Radian
  no longer depends on Radix UI at all; it's Base UI plus `cmdk`.
